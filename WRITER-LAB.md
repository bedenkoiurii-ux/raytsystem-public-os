# Writer-Lab — застосунок: передача досвіду

**Що це.** Застосунок Writer-Lab — нативне вікно macOS, у якому Юрій читає й веде бібліотеку знань. Технічно це **raytsystem** (форк `romarayt/raytsystem-public-os` → `bedenkoiurii-ux/raytsystem-public-os`, робоча гілка **`uk-locale`**), запущений як десктоп-застосунок над текою `~/Writer-Lab/Library`.

**Відкривати проєкт треба тут:** `~/Writer-Lab/raytsystem` — код, фронт і запуск лежать разом.

> **Голосовий пульт із телефона — не тут.** Він ведеться окремо: [PULT.md](PULT.md). Не змішувати: правки в `desktop_app.py` нічого не змінять на телефоні, і навпаки.

> Цей документ — вижимка досвіду, оплаченого помилками. Читати **перед** тим, як щось міняти в UI чи бекенді. Кожен розділ «Пастка» — це те, на що вже витрачено години.

## 1. Архітектура за три хвилини

```
desktop_app.py            ← точка входу: піднімає сервер У СВОЄМУ ПРОЦЕСІ + вікно WKWebView (pywebview)
  └─ src/raytsystem/webapp/   ← бекенд (FastAPI/Starlette)
       app.py                 крос-площинний зріз, обробники помилок цілісності
       document_routes.py     /api/v1/documents… — список, пошук, читання, індекс
       snapshot.py            SnapshotProvider — «перевірений зріз» усіх площин
       security.py            сесія, CSRF, allowlist хостів
  └─ src/raytsystem/documents/index.py   ← DocumentIndex (SQLite-проєкція бібліотеки)
  └─ web/                     ← фронт (React + Vite), збирається у webapp/static/
       src/features/documents/  Documents.tsx, DocumentTree.tsx, DocumentPeek.tsx, SafeMarkdownView.tsx …
```

**Дані:** сама бібліотека — звичайні `.md` файли в `~/Writer-Lab/Library` під git. Застосунок їх **не є джерелом істини** — він проєкція. Індекс лежить у `.raytsystem/documents.sqlite`, службовий стан — в `ops/platform.sqlite`, ledger — у `ledger/`.

**Корінь vault** береться з `RAYTSYSTEM_ROOT`, типово `~/Writer-Lab/Library` (`desktop_app.py`).

## 2. Запуск, збірка, перезапуск

```bash
# запуск застосунку (звичайний спосіб — через Writer-Lab.app, але напряму так):
cd ~/Writer-Lab/raytsystem && uv run --with pywebview python desktop_app.py

# зібрати фронт після будь-якої правки в web/src:
cd ~/Writer-Lab/raytsystem/web && npm run build     # кладе бандл у src/raytsystem/webapp/static/

# перезапуск (Claude робить сам, не просить користувача):
pkill -f desktop_app.py; sleep 2
cd ~/Writer-Lab/raytsystem && nohup uv run --with pywebview python desktop_app.py >/tmp/raytsystem-app.log 2>&1 & disown
```

**Порт 8791 — стабільний навмисно.** origin не змінюється між запусками, тому `localStorage` (тема, тон паперу, формат, відкриті вкладки, активний документ) переживає рестарт. Не робити випадковий порт.

**Правка фронту без `npm run build` не діє.** Застосунок віддає зібраний бандл, а не вихідні файли.

## 3. Пастки, які вже коштували часу

### 3.1. Індекс освіжається сам *(полагоджено 2026-07-27)*
`DocumentIndex` — SQLite-проєкція бібліотеки. Раніше вона будувалася лише на старті сервера, і файли, створені ззовні (конвеєр, git-злиття, правки руками), не з'являлись у дереві до перезапуску.

**Як працює тепер.** GET `/api/v1/documents/index` — точка самолікування: побачив `state: stale` → `index.refresh()` → віддав свіже. Дешево, бо `status()` спершу рахує відбиток дерева (кількість файлів + найновіший `mtime`, ~8 мс на 1400 файлів) і refresh робиться лише коли відбиток розійшовся.

Фронт: хук `useIndexPulse` (`documentHooks.ts`) опитує цей маршрут раз на 10 с; коли `snapshot_id` змінився — інвалідує `listing`, `detail`, `universe`, `timeline`. Приймальня сидить на тому самому пульсі.

**Перевірено в дереві, не в API:** файл, створений ззовні при відкритій вкладці, з'являється за ≤10 с; видалений — зникає.

### 3.2. Три різні речі звуться «Пульт»
Найдорожча плутанина в цьому репозиторії. Перш ніж щось правити — визнач, про яку саме йдеться:

| Що | Файл | Порт | Це воно? |
|---|---|---|---|
| Застосунок на Mac | `desktop_app.py` | 8791 | вікно WKWebView, **про нього весь цей документ** |
| **Пульт із телефона** | `voice_console.py` | 8792 | **саме це Юрій називає «Пультом»** — ведеться окремо, див. `PULT.md` |
| Спостережна палуба | `Library/Pult.html` | — | статичний HTML від `build_deck.py`, до застосунку стосунку не має |

Правки в `Pult.html` нічого не змінять у вікні. Правки в `desktop_app.py` нічого не змінять на телефоні.

### 3.3. Порядок елементів — поле `order`, а не `seq`
`DocumentTree.tsx` сортує:
- **частини піраміди** (діти через `part_of`) — за `properties.order`, інакше за «Блок <римська>» у назві;
- **документи в теці** — теж за `order`, тоді за назвою *(додано 2026-07-25)*.

Будь-яке інше поле (`seq`, `sequence`) фронт **ігнорує**. Хроніки за періодами шикуються за `order` = рік початку, редакційні «Розділ NN» — за номером розділу.

### 3.4. Вирівнювання peek-панелі — вимірювати, не вгадувати
Картка (`DocumentPeek`) — сусід стейджа в `.doc-canvas`, тож стартує від верху канви, тоді як документ має над собою вкладки + шапку + панель режимів. **Не ставити константу відступу** — вона розʼїжджається від шрифта й довжини заголовка. Правильно: `Documents.tsx` через `ResizeObserver` міряє реальну висоту й пише в CSS-змінну `--stage-head-h`.

### 3.5. Світлий «аркуш» — перемапування токенів, не фарбування елементів
Режим читання (`.sheet-light`) працює так: у скоупі контейнера **перевизначаються дизайн-токени** (`--bone`, `--muted`, `--carbon-soft`, `--cyan`…), і весь вміст успадковує. Скоуп поширено і на peek-картки, щоб читання не розпадалося на світлий документ і темну картку поруч.
**Але:** папером стає лише **тіло**; шапка картки лишається службовим темним UI — аркуш це документ, а не інтерфейс.

### 3.6. Крос-площинний зріз падає під фоновим письмом
`SnapshotProvider._load_consistent` знімає узгоджений зріз усіх площин і повторює спробу, якщо стан змінився під час зняття. Коли поруч працює фоновий конвеєр, що переписує файли пачками, зріз не встигає — і користувач бачить **«Зріз недоступний. Перевірений локальний стан недоступний»**.

**Що зроблено:** (а) читання само освіжає протухлий індекс і повторює раз (`document_routes._read`, `recover`); (б) більше спроб із паузою в `snapshot.py`. **Що виявилось справжнім рішенням:** не тюнінг, а **ізоляція** — фонові процеси мають писати в **окремий git-worktree**, а не в каталог, який читає застосунок.

**Урок дорожчий за код:** симптом може «залипнути» у фронті — API вже віддає все справно, а вкладка показує стару помилку. Перш ніж лагодити, перевір API прямо; якщо він OK — просто перезапусти вікно.

### 3.7. API за сесією і CSRF
- Сесія мінтиться на `GET /` → далі потрібна кука: `curl -c jar http://127.0.0.1:8791/ -o /dev/null` і потім `-b jar`.
- Будь-який **POST** вимагає заголовків `Origin: http://127.0.0.1:8791`, `Idempotency-Key: <унікальний>` і зазвичай `expected_snapshot_id` у тілі. Без них — `origin_rejected` / `csrf_rejected`.
- Доступ пускається лише з loopback і мережі Tailscale (`100.64.0.0/10`) — фільтр у `desktop_app.py`.

### 3.8. `/plugin` і решта інтерактивних команд не працюють у застосунку
`/plugin`, `/config`, `/hooks`, `/permissions` відкривають термінальну панель — у вікні Пульта їх немає. Плагіни ставляться з `claude` у Terminal.

## 4. Що вже зроблено (готові можливості)

- **Дерево документів** з роздільниками roots, фільтрами, зрізами (Файли / Нещодавні / Додані / Змінені / Обране), замками на read-only.
- **Вкладки** з фіксацією (pin) і відновленням сесії: застосунок відкривається там, де закрили (маршрут + вкладки + активний документ, `localStorage`).
- **Режими документа:** Читання · Візуально (Milkdown) · Markdown (source) · Diff.
- **Аркуш читання:** світлий папір, тони (теплий / білий / сепія), формати А4 ▯ / А4 ▭ / вільний, керування розміром шрифта.
- **Peek-панель:** клік по вікілінку відкриває картку праворуч **каскадом** (card1 → card2), не покидаючи документ; стрілки згортають каскад.
- **Інспектор:** властивості, посилання, backlinks, історія (immutable revisions, відновлення з попереднім переглядом).
- **Пошук** з мовою запитів (`tag:`, `property:…`, `is:modified`).
- **Граф / Всесвіт** і **Таймлайн** — окремі проєкції над тими самими даними.
- **Віддалений доступ** через Tailscale: бібліотека з телефона.

## 5. Дизайн-система — обовʼязкова

Будь-який новий UI робиться в **дизайн-системі Райта** (скіл `rayt-design`). Джерело істини — `web/src/styles.css`; копія токенів — у бібліотеці, `90-Meta/templates/design-system/`.

Коротко: темна карбонова робоча станція + світлий «аркуш» для читання; іконки — **тільки lucide**; шрифти — IBM Plex Sans / IBM Plex Mono, бренд-заголовки Bricolage Grotesque; мікро-ярлики секцій — UPPERCASE 10–11px, `--muted-2`; статус-пігулки за семантикою (mint = ок, gold = увага, rose = помилка, cyan = дія, periwinkle = агенти, tangerine = бренд).

## 6. Правила роботи, які варто перенести

1. **Перевіряй тим каналом, яким дивиться користувач.** Грепнути бандл чи смикнути API — не доказ. Тричі за одну сесію це призвело до хибного «полагоджено».
2. **Не вгадуй числа — міряй.** Константа відступу = майбутня кривизна.
3. **Правило працює лише як інструмент.** Усе, адресоване памʼяті («не забудь…»), рано чи пізно не спрацює. Роби командою, воротами, вимірюванням.
4. **Перезапуск застосунку — робота Claude**, не користувача.
5. **Фонові процеси — в окремий worktree.** Інакше вони ламають читання.

## 7. Що недороблено (наступні кроки)

- **Peek не має власного «Аркуша»-перемикача** — успадковує стан документа; можливо, це й правильно, але не перевірялося на вимогу.
- **Вирівнювання peek** зроблено через `ResizeObserver`, але не перевірене очима на всіх масштабах шрифта.
- **`document_routes` — 12 читальних маршрутів** уже проходять через `_read_i` з авто-відновленням; решта підсистем (граф, таймлайн) такого захисту не мають.
- **Помилки фронту «залипають»** — варто додати авто-retry при `document_index_stale` замість статичного екрана з помилкою.

## Наступна задача: вікно «Налаштування» (бекенд готовий)

**Принцип Юрія (2026-07-26):** налаштування задаються **в застосунку**, а не в діалозі з ШІ — витрачати токени й розмову на список тек безглуздо. Механізм має бути **загальним**: далі знадобиться задавати теки для інших задач.

**Готове:** `settings_routes.py` — `GET /api/v1/settings/lists` (списки з полем `exists` для кожного запису) і `POST /api/v1/settings/lists/edit` (`{key, value, action: add|remove}`). Перевірено живцем. Нова категорія налаштувань = один рядок у `LISTS`, не нова підсистема.

**ЗРОБЛЕНО 2026-07-27:** `features/Settings.tsx` + маршрут «Налаштування». Список записів (✓/✗ за `exists`), поле «додати шлях», кнопка прибрати, повідомлення бекенда українською. Перевірено живцем: додавання, відмова на неіснуючій теці, прибирання.

**Розширення:** нова категорія додається **лише на бекенді** — один рядок у `LISTS` (`settings_routes.py`). У вікні вона зʼявиться сама, правити `Settings.tsx` не треба.

**Пастка, вже оплачена:** маршрут із **єдиним** параметром `Annotated[Any, Depends(...)]` FastAPI трактує як тіло запиту → 422 на порожньому GET. Писати просто `_session=Depends(require_session)`.

### Нативні можливості macOS у вікні (місток pywebview)

WKWebView, як і будь-який браузер, **не віддає шлях до теки** — лише вміст окремих файлів. Тому «вибрати папку» самим фронтом неможливо. Рішення: `DesktopApi` у `desktop_app.py` передається як `js_api=` у `create_window`, і фронт кличе `window.pywebview.api.pick_folder()` — відкривається **нативний діалог macOS**.

Так само сюди додаються інші нативні речі (показати у Finder, вибір файлу): метод у `DesktopApi` → доступний у вікні як `window.pywebview.api.<метод>()`. У браузері місточка немає — фронт має перевіряти наявність і мати запасний шлях (у Налаштуваннях це введення шляху текстом).

## Агенти живуть усередині Writer-Lab, а не в launchd

**Рішення Юрія (2026-07-27):** Writer-Lab — агентна система, тож її агенти мають бути **в ній**. Системна служба macOS означала б, що частина системи живе поза системою: засмічує ОС, керується з термінала, не бачить власного стану. Створений був `com.writerlab.watchdog` — **видалено**.

**Як зроблено:** `webapp/agents.py` — `InboxWatcher` як `asyncio`-задача, що стартує/зупиняється разом із застосунком (`on_event startup/shutdown` у `app.py`). Сервер працює в тому самому процесі, що й вікно, тож агент — природна його частина.

**Ціна, прийнята свідомо:** стеження працює, поки відкритий застосунок. Це чесніше за приховану службу, яка сканує диск за спиною автора.

**Дешевизна — принцип, не оптимізація.** Агент рахує відбиток тек (кількість файлів + найновіший `mtime`) за мілісекунди й **нуль токенів**; модель прокидається лише коли відбиток змінився. До цього постійний цикл варти будив Claude кожні кілька хвилин — шість прогонів поспіль закінчилися висновком «усі файли дублікати».

**У вікні:** Налаштування → «Автономне стеження» — стан, кількість тек, чи працює варта, останнє спрацювання, вимикач. Стан читається з памʼяті процесу й файлів, **без моделі** — як екран стану голосового пульта (`PULT.md`).

*(`com.writerlab.varta` — окрема щоденна ранкова варта о 7:00, її це не стосується.)*

## Двофазна варта: модель не працює без «у роботу»

**Рішення Юрія (2026-07-27):** розбір матеріалу починається ПІСЛЯ його «у роботу», не до. Привід: варта розібрала всі 29 файлів теки `!!ЕССЕ!!`, і 26 виявились дублікатами вже наявного — судження витрачено на те, що автор відхилив би не читаючи.

```
зміна в теці → inbox_scan.py (0 токенів) → queued → [автор: «У роботу»] → in_work → варта (Claude) → proposed → [автор: резолюція] → accepted
```

**Що модель робить дарма, а що ні.** Упізнання не потребує судження: sha256 проти журналу, `grep` по `source_origin` у бібліотеці (шлях у frontmatter збігається буквально або не збігається зовсім), конвертація `convert.py`. Саме це варта раніше робила моделлю. Судження — тип, місце, сутності, джерела — фаза 2.

**Де межа стоїть фізично:** `ALLOWED` у `reception_routes.py`. З фази `queued` дозволено лише `in_work` і `rejected` — «прийняти» нерозібране повертає 409 `wrong_phase`. Правило-як-ворота, не правило-як-пам'ять.

**Агент:** `agents.py` кожен тік (а) жене `inbox_scan.py`, якщо відбиток тек змінився; (б) будить варту **лише якщо в черзі є `in_work`**. У стані агента видно обидва лічильники.

## Мапа сюжетів — четверта проєкція

**Задум Юрія (2026-07-27):** «Тема розгортається в кількох вимірах: бере початок в одній географічній точці, набуває розвитку в іншій, закінчується в третій». Ліворуч географія, праворуч розповідь — період, вкладки «Сюжети / Періоди», під назвою сюжету реперні точки (рік · подія · місце).

**Сюжет = документ**, до якого прив'язані події через секцію «## Згадується в». Окремого поля не заводили: розділ книги вже є одиницею розповіді, і 41 сюжет зібрався без жодної правки в даних. Той самий механізм, що в `build_apparatus.py`.

**Три пастки, оплачені тут:**

1. **Місце події — поле `place:`, не вікілінки тіла.** Картка «Чорнобильська катастрофа» згадує `[[Катинь]]` як приклад тієї самої державної брехні — і мапа ставила туди точку аварії.
2. **У `place:` часто записаний рух**, а не точка: «Київ → Володимир-на-Клязьмі → Москва». Це готовий вектор події — шукаємо всі відомі місця в порядку появи в рядку.
3. **Час живе в подіях, не в місцях.** У картці місця `time_start` означає заснування й стоїть в одиниць: повзунок виходив 1589–1616 на всю історію. Через події діапазон став 1169–2022.

**Порядок — хронологічний.** Спершу сортував «спершу ті, що лягають на мапу»; Юрій: «якщо це шкала часова, то й порядок хронологічний».

**Областей не малюємо** — рішення Юрія, категорично: контурів історичних територій у бібліотеці немає, домальовувати кордони на око означає видати вигадку за факт. Територія лишається точкою з підписом.

**Періоди не вигадуємо** — беремо виписані в бібліотеці (8 хронік за десятиліттями 1917–2019). Для давнішої історії їх у матеріалі немає, і це сказано у вкладці, а не приховано.

**Дрібне, що коштувало часу:** list-API віддає 409 на `limit>50`; новий маршрут треба додати в SPA-allowlist `app.py`; підписи налазять — груба сітка антиколізії, при зумі дрібнішає; контур (Natural Earth 110m, обрізаний) лежить у бандлі окремим чанком, бо CSP має `connect-src 'self'`.

## Шар знань: чому був порожній і що з ним зараз

**Стан на 2026-07-28:** `claims 1`, `sources 1`, `entities 0`. FTS по документах (1605) працює давно й окремо — це різні речі: FTS шукає по тексту, шар знань тримає твердження з доказами й статусом опори.

**Чому був порожній.** Не через команди. Дефолтний верифікатор схвалень — `ApprovalVerifierUnavailable`, заглушка, що відмовляє **завжди**: апстрімовий контур розрахований на зовнішній сервіс криптопідпису. `promote` не міг спрацювати на жодному справжньому документі від першого дня. Полагоджено `WorkspaceApprovalVerifier` — вмикається лише при `--approval`, прив'язка схвалення до хеша кандидата, політик, вікна часу й scope лишилася вся; знято тільки доказ особи підписанта.

Робочий ланцюг:

```
raytsystem prepare <файл> --root .
python3 raytsystem/scripts/approve_run.py <run_id> --root ~/Writer-Lab/Library
raytsystem promote <run_id> --root . --approval ops/approvals/incoming/<apr>.json
raytsystem rebuild-index --root .
```

Індекс живе в `.raytsystem/index.sqlite`. Файл `index.sqlite` у корені корпусу — порожня пустушка від `rebuild-index`, не плутати.

**Три борги, які лишилися (жоден не про гроші):**

1. **Пропонувальник claim'ів — заглушка.** `ingestion.py:2295` бере `evidence_items[0]` і робить із першого спана єдине твердження на документ. Прогін бібліотеки дасть 1605 claim'ів «перше речення документа».
2. **`M1 accepts exactly one claim proposal per response`.** Контур приймає рівно одну пропозицію на документ — скільки моделей не став, з розділу на 40 абзаців вийде одне твердження. Знімати доведеться незалежно від того, хто пропонує.
3. **Ретракції немає.** `tombstone` у генераціях лише читається, ставити його нікому; єдиний шлях створити генерацію — `promote`. Шкала опори має 🔴 «спростовано», а зняти твердження нічим. Писати `retract` варто тоді, коли шар знань стане справжнім — на порожньому корпусі це механізм для системи, якої ще нема.

**Про детермінізм і локальні моделі.** `ingestion.py:2341` перераховує `proposal_response_id` із хешу запиту й пропозицій і кидає `IntegrityError` при розбіжності — тобто пропонувальник мусить бути відтворюваним побітово. Хмарна модель цього не гарантує (постачальник підмінить версію під тим самим іменем), локальна з фіксованими вагами й `temperature=0` — гарантує. Тому конвеєр знань правильно розкласти надвоє: локальна модель робить витяг по всьому корпусу безкоштовно й детерміновано, топ-модель отримує витягнуте й виносить судження про опору. Витяг перевіряється звіркою з джерелом посимвольно; судження вимагає трьох незалежних джерел, і саме там дешева модель вигадує посилання.

**Екстрактор навчено бачити markdown** (`native_text` 1.1.0). Доказом стає проза: відсіюються frontmatter, заголовки, огорожі коду з умістом, роздільники, розмітка таблиць. Фільтр, не перетворення — excerpt лишається дослівним, локатори точними. Документ із самих заголовків падає назад на заголовки, щоб не втратити коротку нотатку. Перевірка: `tests/test_prose_extraction.py`.

## Двоповерховий конвеєр знань

**Поверх 1 — витяг, локальна модель, безкоштовно.** `scripts/propose_local.py` бере evidence pack підготованого run і питає `qwen2.5:32b` через Ollama, що саме стверджує кожен сегмент. Модель формулює — і тільки. Вона не оцінює істинність, не шукає джерел, не присвоює статус за шкалою опори, і не має інтернету за побудовою.

**Поверх 2 — судження, Claude.** Статус за шкалою опори вимагає звірки з трьома незалежними джерелами; локальна модель на цьому вигадує посилання, а вигадане посилання — аварія системи.

**Чому локальна модель тут не гірша, а краща.** `ingestion.py` перераховує `proposal_response_id` із хеша запиту й самих пропозицій і кидає `IntegrityError` при розбіжності — відповідь мусить бути відтворюваною побітово. Локальна модель із фіксованими вагами, `temperature=0` і сталим seed це дає. Хмарну постачальник підмінить під тим самим іменем — і вся минула робота перестане звірятися.

Повний шлях документа в шар знань:

```
raytsystem prepare <файл> --root .
python3 raytsystem/scripts/propose_local.py <run_id> --root ~/Writer-Lab/Library
raytsystem proposal import <run_id> ops/staging/<run_id>/proposal_response.json --root .
python3 raytsystem/scripts/approve_run.py <run_id> --root ~/Writer-Lab/Library
raytsystem promote <run_id> --root . --approval ops/approvals/incoming/<apr>.json
raytsystem rebuild-index --root .
```

**Пастки, оплачені тут.** 32B на батчі з шести абзаців вибиває таймаут — батч 3, `num_predict` 400, `num_ctx` 8192; без `num_predict` модель меле хвилинами. Збій одного батча не валить прогін: його сегменти просто лишаються без тверджень.

**Що модель відкидає.** З 12 сегментів розділу 07 — 8 тверджень, 4 відкинуто як риторичні переходи («Саме тут починається історія…» лишається, «Але історія не зупиняється» — ні).
