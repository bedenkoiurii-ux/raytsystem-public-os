# Відхилення форку `uk-locale` від вихідного raytsystem

Реєстр навмисних змін у чужому коді. Потрібен для двох речей:
щоб при підтягуванні оновлень згори було видно, **де чекати конфлікту**,
і щоб через півроку ніхто не питав, навіщо тут дивна рекурсія.

Правило: тримати площу дотику мінімальною. Не переписувати функції —
вставляти якнайменше рядків у якнайменшу кількість точок. Кожна зміна
позначена в коді коментарем `# ФОРК uk-locale:`.

```
grep -rn "ФОРК uk-locale" src/
```

---

## 1. Індекс документів більше не протухає за годинником

**Файл:** `src/raytsystem/documents/index.py` · `status()` і новий `_tree_fingerprint()`

**Було.** Індекс оголошував себе застарілим **через 60 секунд після побудови**, незалежно від того, чи щось змінилося:

```python
if age.total_seconds() > 60:
    state = "stale"
```

А стартовий гак `initialize_document_module` перебудовує індекс повністю, якщо стан не `current`. Через хвилину після будь-якої побудови стан завжди не `current` — отже **кожен запуск застосунку = повний ребілд**.

**Стало.** Застарілий = дерево справді змінилося. Відбиток — кількість файлів плюс найновіший `mtime`, зберігається в `meta.tree_fingerprint`.

**Навіщо.** У вихідному дизайні індекс — одноразова проєкція, свіжість якої треба доводити; для контрольної панелі над git це виправдано. Для бібліотеки, що росте до десятків тисяч документів, це нескінченна переіндексація.

**Ціна.** Відбиток — **5 мс** на 1453 документи, близько 90 мс на 15 000. Повний ребілд — **9 секунд**.

---

## 2. `refresh()` рахує дельту сам

**Файл:** `src/raytsystem/documents/index.py` · `refresh()` і новий `_changed_paths()`

**Було.** Умова на вході була круговою:

```python
if not paths or status["state"] != "current":
    return self.rebuild()
```

Інкремент дозволявся лише коли індекс `current` — тобто рівно тоді, коли оновлювати нема чого. Будь-яка правка ззовні тягла повний ребілд.

**Стало.** Ребілд лише коли база відсутня чи зламана або змінився конфіг. Інакше — порівняння `(шлях, mtime_ns)` дерева з таблицею `documents` і точкове оновлення. Дельта більша за 256 файлів → ребілд (дешевше).

**Три пастки, знайдені при налагодженні** — якщо переноситимеш, не загуби:
- обхід мусить бачити **всі файли, а не лише `.md`**: індекс тримає й зображення, і різниця наборів робила цілі теки «вічно зниклими»;
- **видалене визначати існуванням файлу**, а не різницею множин — з тієї ж причини;
- **файли понад `max_file_bytes` пропускати**: індекс їх не бере взагалі, і без фільтра вони вважалися б новими вічно.

**Ціна.** Холостий прогін — **55 мс** (було 9 с). Оновлення одного файлу — близько 400 мс.

## 3. Документ лікує себе сам замість «Зріз недоступний»

**Файл:** `src/raytsystem/documents/index.py` · `detail()`

**Було.** Файл, змінений поза застосунком, давав жорстку помилку:

```python
if digest != str(row["content_sha256"]):
    raise DocumentIndexError("Document changed after the current index snapshot")
```

Інтерфейс показував «Зріз недоступний. Запустіть перевірку цілісності» — тобто через один документ пропонувалось перевіряти всю бібліотеку.

**Стало.** На розбіжності хешу оновлюємо **рівно цей файл** і читаємо ще раз. Не збіглося й після оновлення — тоді помилка доречна, це вже справжня біда.

**Обмеження, свідоме.** Лікуємо лише звичайне читання. Якщо викликач передав `expected_snapshot_id`, він стежить за версією (редакторський потік) — там розбіжність є значущою подією, і глушити її самолікуванням не можна.

**Ціна.** 488 мс на перше відкриття зміненого документа замість помилки.

## 4. Сторінка «Конвеєри» — робочий стан фонових циклів

**Файли:** новий `src/raytsystem/webapp/conveyor_routes.py` · новий
`web/src/features/ConveyorsView.tsx` · дотик до `webapp/app.py`,
`web/src/presentation.ts`, `web/src/app/App.tsx`, `web/src/styles.css`

**Навіщо.** Конвеєри Writer-Lab — сім безголових циклів `claude -p` — до цього
можна було спостерігати лише `tail -f` у терміналі. Сторінка показує їхній стан
у тому самому вікні, де ведеться бібліотека: етап усередині прогону, тривалість
проти звичайної, чергу, денний бюджет, незлиті коміти гілки.

**Нуль моделі.** Читання файлів `~/.writer-lab`, черг і `git log`. Сторінка,
що показує, чи не палить конвеєр гроші, сама коштувати токен не має права.

**Площа дотику мінімальна.** Уся логіка — у двох НОВИХ файлах; у чужих чіпнуто
рівно чотири точки, кожна — один рядок:
- `app.py`: імпорт `create_conveyor_router`, `include_router`, `"conveyors"` у `_SPA_ROUTES`;
- `presentation.ts`: запис `conveyors` у `routeCopy`;
- `App.tsx`: іконка в мапі маршрутів, `case "conveyors"` і пункт у списку навігації;
- `styles.css`: блок `.cv-*` дописаний у кінець, наявних правил не змінено.

**Конфлікт при підтягуванні згори** можливий лише в цих чотирьох файлах, і лише
якщо upstream перебудує реєстрацію маршрутів або список навігації. Обидва нові
файли конфліктувати не можуть.

**Ціна.** Один запит — ~60 мс, з них 57 мс — живий прогін воріт `card_order.py`
по черзі карток. Оновлення раз на 30 с.

## 5. Локальний адаптер Claude не бачив автентифікації на macOS

**Файл:** `src/raytsystem/execution/adapters.py` — `_RUNTIME_ENV_ALLOWLIST` і
`ClaudeLocalAdapter.build_command`

**Дві правки, обидві по одному рядку.** Зроблені під час пілота платформи 01.08, але
**чинні незалежно від нього**: це виправлення для macOS, а не налаштування пілота.
Тому вони лишились у коді після відкату прапорців.

**1. `USER` додано в allowlist середовища.** Облікові дані Claude Code на macOS лежать
у Keychain, і пошук у ньому ключується на `$USER`. Без цієї змінної `claude auth status`
у зрізаному середовищі відповідає `loggedIn: false`, хоч сесія цілком чинна.
Встановлено бісекцією по одній змінній:

```
нічого   → loggedIn: false      USER     → loggedIn: TRUE
LOGNAME  → false                SHELL    → false
TMPDIR   → false                XPC_SERVICE_NAME → false
```

Ізоляція при цьому лишається списком, а не «успадкувати все» — додано рівно одну змінну,
і жодного секрету через середовище не передається.

**2. `--bare` прибрано з команди.** Він не читає сесію з Keychain і відповідає
«Not logged in» **навіть при чинному логіні**. Перевірено голою командою: `claude
--print --bare` падає, та сама команда без `--bare` відповідає. Решта прапорців
(`--permission-mode dontAsk`, `--disable-slash-commands`, `--strict-mcp-config`,
`--mcp-config`, `--tools`) працює й лишена незмінною.

**Перевірка після злиття згори:**

```bash
env -i HOME="$HOME" PATH="$PATH" USER="$USER" claude --print --output-format text \
  --permission-mode dontAsk --tools "Read,Glob,Grep" <<< "скажи: ок"
```
Очікуємо `ок`. Якщо `Not logged in` — котрась із двох правок загубилась.

**Ризик при підтягуванні:** upstream може навмисно повернути `--bare` як частину
контракту ізоляції. Тоді питання доведеться вирішувати наново, а не відновлювати
правку автоматом — саме тому тут описано **навіщо**, а не лише **що**.

## Якщо колись підтягувати оновлення згори

1. `grep -rn "ФОРК uk-locale" src/` — усі точки дотику.
2. Конфліктувати можуть лише `status()`, `refresh()` і `detail()` у `documents/index.py`. Решта файлу недоторкана.
3. Перевірка після злиття:
   ```
   uv run --with pydantic --with pyyaml python3 -c "…"   # див. розділ «Ціна» вище
   ```
   Очікуємо: `status()` ≈ 5 мс і `current` без змін на диску; холостий `refresh()` ≈ 55 мс; правка файлу ззовні → `stale` → після `refresh()` → `current`.
4. **Головний ризик:** upstream може перебудувати саму модель свіжості (індекс як одноразова проєкція — це його дизайнерське рішення, а не недогляд). Тоді ці зміни доведеться переносити думкою, а не автоматом. Саме для цього тут описано **навіщо**, а не лише **що**.
